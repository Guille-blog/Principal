# Decisiones de diseño (Fase 1)

| # | Decisión | Alternativas | Motivo |
|---|---|---|---|
| D1 | **Electron 33 + React 18 + TypeScript + Vite** (`electron-vite`) | Tauri, WPF/.NET | Instalador `.exe` probado con `electron-builder`, el mismo motor Chromium en todos los equipos y exportación a PDF nativa (`printToPDF`). Tauri genera un instalador más pequeño, pero depende de WebView2 y su toolchain Rust complica el mantenimiento. |
| D2 | **Diagrama propio en SVG**, virtualizado en filas y columnas | DHTMLX Gantt, Bryntum, Frappe | Sin licencias de pago y control total del dibujo crítico (barras de holgura, vínculos conductores). Se dibujan sólo las filas y días visibles, así que 500 tareas no frenan la vista. |
| D3 | **Motor de cálculo puro** (`src/core`), sin dependencias de la interfaz y con tests Vitest | Calcular en los componentes | Permite verificar el CPM de forma aislada y reutilizarlo en la Fase 2 (importación, informes). |
| D4 | **Cálculo en ordinales laborables** con intervalos semiabiertos `[ES, EF)` | Fechas con horas, como MS Project | Fines de semana, festivos y desfases (que se expresan en días laborables) se resuelven en un solo sitio. Los hitos son instantes (`ES = EF`) y se dibujan en la frontera del día. |
| D5 | **Notación de predecesoras por número de fila**, guardada internamente por `uid` estable | Guardar el número de fila | Es lo que el usuario conoce de MS Project. Al insertar o mover filas el texto se renumera solo y los vínculos no se rompen. |
| D6 | **Mover a mano una tarea con predecesoras crea una restricción «No comenzar antes de»** (icono de chincheta, aviso y botón para quitarla) | Ignorar el movimiento; programar todo a mano | Es el comportamiento de MS Project, pero aquí se hace **visible**. Así se evita el problema habitual de restricciones ocultas que falsean el camino crítico. |
| D7 | **Crítica = holgura total ≤ 0** (incluye las negativas). Casi crítica = 0 < holgura ≤ umbral (5 días por defecto, configurable) | Sólo holgura = 0 | Si hay fecha contractual incumplida, las tareas con holgura negativa son las que más urgen. |
| D8 | **Fin tardío de las tareas sin sucesoras = fin del proyecto** (o fecha contractual si es anterior) | Fin tardío propio, como MS Project con "varios caminos críticos" | Así una tarea suelta aparece con la holgura que realmente tiene, y además se avisa de que está suelta. |
| D9 | **Vínculos a capítulos (tareas resumen) no admitidos en la Fase 1**: se bloquean al escribirlos y, si vienen en un archivo, se ignoran con aviso | Repartirlos entre las tareas del capítulo | Con vínculos CC o CF hacia un resumen el reparto no es equivalente y daría un camino crítico erróneo. Mejor ser explícito. |
| D10 | **Las dependencias circulares se bloquean al editar**, indicando el ciclo. Si llegan en un archivo, el cálculo crítico se suspende y se muestra el aviso | Permitirlas y avisar | Un ciclo invalida todo el CPM; no tiene sentido guardar un estado así. |
| D11 | **Archivo `.gantt.json` con `schemaVersion`**, validado y migrado al abrir. Guardado atómico (escribe en un temporal y lo renombra) | Formato binario o SQLite | Es legible, se puede comparar entre versiones y es fácil de importar o exportar en la Fase 2. El guardado atómico evita corromper el archivo si falla la escritura. |
| D12 | **Autoguardado de recuperación** cada 30 s en la carpeta de usuario, con oferta de restaurar al arrancar | Autoguardar sobre el archivo original | Sobrescribir sin permiso el archivo del usuario es peligroso. La copia de recuperación cubre los cierres inesperados. |
| D13 | **Deshacer y rehacer ilimitados** mediante instantáneas inmutables | Pila de comandos | Más simple y robusto; el coste de memoria es despreciable con cientos de tareas. |
| D14 | **Festivos nacionales calculados** (Pascua por Meeus/Jones/Butcher), con aviso de revisar el BOE y añadir los autonómicos y locales | Tabla fija descargada | Funciona sin conexión y para cualquier año. El calendario oficial puede variar (traslados de las comunidades autónomas), así que **no se da por correcto sin revisarlo**. |
| D15 | **Seguridad**: `contextIsolation`, `sandbox`, sin `nodeIntegration`, y el preload expone sólo una API mínima | — | Es la configuración recomendada por Electron. No se añade CSP por `<meta>` porque rompería el modo desarrollo; la app sólo carga contenido local. |
| D16 | **Modo navegador** (`npm run web`) con una alternativa a la API de escritorio (descargas y `localStorage`) | Sólo Electron | Permite probar la interfaz automáticamente con Playwright y hacer demostraciones rápidas. |
